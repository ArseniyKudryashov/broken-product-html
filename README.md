# Зламаний продукт №1 — «Переговорки, демо»

Маленький продукт: список кімнат із фільтром за місткістю (`index.html` + `app.js`) і форма запиту (`request.html`). Один `style.css`.

Учора все працювало. Сьогодні в підтримку прийшло **чотири тикети**. Кожен — окрема помилка, і кожна живе на **своєму шарі**: HTTP, HTML, CSS, JavaScript. Ваша задача — для кожного тикета визначити шар, знайти причину інструментами, виправити мінімальним diff і заповнити `DIAGNOSIS.md`.

## Тикети від користувачів

| # | Що кажуть користувачі |
|---|---|
| 1 | «Сайт відкрився голий — без кольорів і оформлення, як у 1998 році». |
| 2 | «Надсилаю запит на бронювання — адміністратор отримує заявку **без часу початку**. Дата є, хто бронює є, часу немає». *(На цій сторінці дані після надсилання видно в адресному рядку — навмисно.)* |
| 3 | «На головній кнопка „Показати“ **не натискається**. І випадайка з місцями теж не відкривається мишкою». |
| 4 | «Обираю „від 6“ — пише „Немає кімнат з такою місткістю“, хоча кімнати B (10) і C (6) підходять». *(Цей тикет можна перевірити лише після того, як полагоджено №3 — або через клавіатуру: Tab до кнопки, Enter.)* |

## Правила

- Без ШІ-агента для пошуку причин. MDN — можна.
- Для кожного тикета спочатку назвати **шар** (HTTP / HTML / CSS / JS) і **інструмент**, яким ви це побачили (Network / Elements / Styles / Console / Sources+брейкпоінт).
- Мінімальне виправлення, один коміт на тикет, `DIAGNOSIS.md` заповнений.
- Перевірка після кожного виправлення: три сторінки, нічого не зламалось.

## Як запускати локально

Відкрити `index.html` у браузері (або Live Server). Для тикета №1 відкрийте Network — помилку видно й локально.
